## Implementation Steps

1. **Banner 顶部右侧对齐 & Logo 副标题简化**（App.jsx L2395-L2488）
   - 把右侧 L2413 `flex items-center gap-1.5 sm:gap-3` → 加 `content-center flex-wrap` 并给所有按钮统一 `h-9 sm:h-9 max-sm:h-11` 规范（目前 UserSwitcher h-10/OperatorSelectorChip h-10 和其它 h-9 不一致）；把两个 chip 的 className 从 h-10 改成 `h-9 sm:h-9 max-sm:h-11` 保持一致
   - OperatorSelectorChip 内部 subtitle 「管理员视角 · 查看个人」简化为「管理员视角 / 个人」，UserSwitcher 内部 subtitle 「当前登录人 · 模拟」简化为「当前登录人」
   - L2404 `Multi-Account Monitor v3.4` → 简化为 `监测看板 · v3.4`，sm 端 10 个字符内
2. **历史爆款 Drawer 三选项卡改造**（App.jsx L2008 `ViralHistoryDrawer`）
   - Drawer header 下方加 `Tab 3 段 segmented control`（爆款内容 / 运营排行 / 平台排行）
   - 新增 `useMemo` 聚合：
     - `byOperator`：group by operator_uid，计算 count / sum(post.views) / sum(post.likes) / avg(engagementDelta)，按 count desc
     - `byPlatform`：group by platform_key，计算 count / sum(post.views) / sum(post.likes) / avg(surgeIndex)，按 count desc
   - 运营排行卡片：运营头像 + 名 + 爆款数 badge + 总曝光（AnimatedNumber）+ 占比条
   - 平台排行卡片：平台名 + 色点 + 爆款数 badge + 总曝光（AnimatedNumber）+ 占比条
3. **覆盖增长 日/周/月 周期切换**（App.jsx GrowthChart 调用处 2 处 + 新增聚合 helper）
   - 新增 state：`const [granularity, setGranularity] = useState('day')`（'day' | 'week' | 'month'）
   - 新增纯 function `aggregateTrend(trend, granularity)`：按自然周/月 sum 所有非 date 字段，date 按 `8/第1周 / 8月` 格式；注意平台页的单平台 trend 也要走此函数
   - L2287 平台页：把 `span 日维度` 改成 3 段 segmented chip（日 / 周 / 月），选中态 bg-indigo-500 白字，非选中态 bg-ink-50/60 灰字
   - L2740 首页：同上
   - GrowthChart 调用改用 `aggregateTrend(原data, granularity)` 的返回值
4. **AI 诊断点击异常 → 弹详情 Modal**（新 DiagnosisDetailModal + App.jsx 接入）
   - 新建 `DiagnosisDetailModal.jsx`，严格遵守 Modal 居中模板：
     - AnimatePresence sibling：overlay motion.div（z-40 fixed inset-0）+ 普通 div（fixed z-50 left-1/2 top-1/2，style transform: translate(-50%,-50%)）包裹 motion.modal
     - 内容：header 严重度色条 + 标题 + 关闭；body 描述/建议；footer 「跳转到相关对象」按钮
   - App.jsx 新增 `const [activeDiagnosis, setActiveDiagnosis] = useState(null)`
   - L2525 `scopedDiagnosis.map` 的 button `onClick` 改为 `() => setActiveDiagnosis(d)`
   - App.jsx 渲染 DiagnosisDetailModal：`open={activeDiagnosis !== null}`，传 diagnosis、data、onClose、onNavigateOperator/onNavigatePlatform 回调
5. **最终验证**：`npm run build` exit 0 + 浏览器点击验证以上 5 点无错位

## Dependencies and Considerations
- `framer-motion` 居中模板严格遵守：外层普通 div 定位，内层 motion 只负责 opacity/y/scale（上次 CENTERING FIX 验证通过）
- 新增 DiagnosisDetailModal 标签闭合顺序严格参考 PlatformDetailModal 的 v4.0 CENTERING FIX 最终版结构
- segmented control 使用 3 个 button 包一层 rounded-xl + 选中项 bg-indigo-500 shadow-sm，不引入新库
- aggregateTrend 按自然周而非 7 天滑动，避免周一/周日边界错乱（简单实现：按日数组下标 `i//7` 分桶）
- viralHistory 可能有 `operator_uid=null`（早期条目），归到「未分配」组
- 不改 `generateWeeklyReportMarkdown` 与 mock 数据结构，全部向后兼容

## Risks
- **风险1**：Aggregate trend 时如果 trend 数据列有字符串非数字会 `+=` 拼接 → 处理：`Number(v) || 0`
- **风险2**：3 Tab ViralHistoryDrawer 高度溢出 → 用 `flex-1 overflow-y-auto` 包住 Tab 内容区
- **风险3**：Banner 统一 h-9 时 mobile 端 UserSwitcher 头像 + 文字行高不足 → max-sm 保持 max-sm:h-11 不变
- **风险4**：DiagnosisDetailModal target_ids 在 latestRecords 找不到 → 显示「对象已下线」占位
